# PLAN.md: Создание micro-MVP «Кто выгуливает Бориса»

## 1. Текущий статус

- Приоритет: собрать минимально работающий главный сценарий с постоянным состоянием в SQLite.
- Текущее состояние: минимальная основа Node.js-приложения, SQLite-хранилище, схема и создание пяти слотов текущей даты реализованы, проверены и приняты студентом; фаза основы постоянного состояния завершена.
- Основная цель цикла: реализовать и фактически проверить продукт от локального запуска до итогового smoke-check.
- Обязательные ограничения:
  - использовать только Node.js, npm и SQLite;
  - хранить постоянное состояние только в SQLite;
  - защищать повторную запись в слот атомарно на сервере;
  - использовать только синтетические ФИО и данные;
  - не добавлять функции вне `spec.md`;
  - не выполнять commit, push, публикацию, удаление данных или деплой без отдельного явного запроса;
  - выполнять за одну итерацию только один явно выбранный шаг;
  - не считать шаг завершённым без фактической проверки.
- Основной контекст проекта: `spec.md`, `AGENTS.md`, `README.md` и этот `PLAN.md`.
- Текущий активный шаг: не выбран после принятия шага 6; шаг 7 не начат.

## 1.1. Главный сценарий прогулки

1. Пользователь запускает приложение локально предусмотренной npm-командой.
2. Открывает общую страницу «Кто выгуливает Бориса».
3. Видит текущую дату.
4. Видит ровно пять слотов прогулки: `09:00`, `11:00`, `13:00`, `15:00` и `17:00`.
5. Отличает свободные слоты от занятых.
6. Выбирает свободный слот.
7. Вводит синтетическое ФИО и подтверждает запись.
8. Видит, что слот стал занятым и показывает введённое ФИО.
9. Из ранее открытой страницы во втором браузере повторно пытается занять тот же слот другим ФИО.
10. Получает понятный серверный отказ, а первоначальная запись не меняется.
11. Обновляет страницу или открывает приложение во втором браузере.
12. Видит сохранённое состояние слотов.
13. Проходит главный сценарий на широком и узком экране без помех.

Дополнительная проверка кормления вне главного сценария:

1. Пользователь видит понятное пустое состояние карточки до первой отметки.
2. Отмечает кормление синтетическим ФИО.
3. Видит в карточке последнего кормления новое ФИО и время.
4. Обновляет страницу и видит сохранённое состояние карточки.

## 4. Прямые зависимости и проверки

- `spec.md` — единственный источник продуктовых требований, SQLite-схема, семь DoD, smoke-check и границы.
- `PLAN.md` — текущий активный шаг, очередь работ, статусы и фактические результаты проверок.
- `AGENTS.md` — постоянные правила работы агента и ограничения действий.
- `README.md` — фактическое описание проекта, проверенный запуск, сценарий и границы.
- `package.json` — зависимости и предусмотренные npm-команды после создания основы проекта.
- SQLite-файл — постоянное состояние слотов и кормлений после реализации хранилища.
- Git diff — проверка фактического состава каждой итерации и отсутствия лишних изменений.
- Браузер — проверка интерфейса, главного сценария, широкого и узкого экрана.
- Второй браузер или другой контролируемый запуск — проверка общего постоянного состояния.

## 5. Критерии готовности проекта

- Приложение запускается локально командой, указанной в README.
- SQLite-файл содержит таблицы `walk_slots` и `feedings` по схеме из `spec.md`.
- Для текущей даты существуют ровно пять фиксированных слотов.
- На странице показаны текущая дата и пять слотов.
- Свободные и занятые слоты визуально различаются.
- Свободный слот можно занять корректным синтетическим ФИО.
- Занятый слот показывает ФИО первоначально записавшегося.
- Повторная запись атомарно отклоняется сервером.
- Первоначальная запись не меняется после конфликта.
- Прогулки и кормления сохраняются после обновления страницы.
- То же состояние видно во втором браузере или другом контролируемом запуске.
- Карточка последнего кормления показывает и обновляет ФИО и время.
- Главный сценарий выполняется на широком и узком экране.
- Все семь DoD подтверждены фактическими результатами.
- Каждый завершённый шаг содержит описание выполненной проверки.
- README и PLAN соответствуют текущей версии продукта.
- Просмотрен итоговый diff.
- В проекте нет функций вне `spec.md`, реальных данных и секретов.
- Границы решения и один следующий инженерный шаг указаны без заявления о промышленной готовности.
